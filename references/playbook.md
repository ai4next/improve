---

## 1. 优先级

**按优先级排序，每轮只做最高优先级的一件事。** 一轮改多个维度，分数升降无法归因。

| 优先级 | 触发条件 | 为什么排这个位置 |
|---|---|---|
| **P0** | 有 `error` 级诊断 | 客观损坏。悬空引用会让 agent 直接卡住 |
| **P0** | 有 `RT*` 命中 | runtime drift 会让其他 agent 拒绝安装，skill 直接失效 |
| **P1** | `FL*` / `CP*` 命中 | 失败分支与检查点决定「跑起来会不会翻车」 |
| **P2** | `SP*` / `FM0*` 命中 | 具体性与入口质量决定「能不能被选中、能不能被执行」 |
| **P3** | `ST*` 结构类 / `SZ*` 体积类 | 影响可读性与上下文成本，不影响正确性 |
| **P4** | 只剩 `info` | 触顶信号，见 §5 |

## 2. 诊断码 → 修法

### P0 · 客观损坏

| 码 | 修法 |
|---|---|
| `FM001` | 在文件第 1 行补 `---`，末尾补 `---`。检查有没有 BOM 或前置空行 |
| `FM002` | 补 `name:`。必须是小写短横线，与目录名一致 |
| `FM003` | 补 `description:`。见 §3 的入口模板 |
| `FM004` | `name` 改成 `[a-z0-9-]`，≤64 字符 |
| `FM006` | 砍长尾关键词与重复表述。**先删「不适用」以外的枚举**，它是长度大头 |
| `ST004` | 三个选择：① 改路径 ② 补文件 ③ 删掉这句引用。**不要留着** |

### P0 · Runtime drift

| 码 | 修法 |
|---|---|
| `RT001` | 按 [`runtime-neutrality.md`](runtime-neutrality.md) §3 改写。先读上下文确认不是元陈述 |
| `RT002` | badge 换成三个中立 badge |
| `RT003` | 补三层结构：自动检测一行命令 + 各 runtime 路径表 + 作为参考资料兜底 |

### P1 · 失败模式与检查点

| 码 | 修法 |
|---|---|
| `FL001` | 补一节「失败模式」，三段式表格。**从真实踩过的坑写起**，不要编通用条目 |
| `FL002` | 把散在正文里的「如果…就…」抽出来做成表 |
| `FL003` | 加第三列「仍失败兜底」。这一列回答的是「第二次失败该停手还是继续」 |
| `CP001` | 把「等用户确认」改成 `🔴 CHECKPOINT · <决策名>`，并写清确认什么 |
| `CP002` | 找出流程里**不可逆**的动作（写盘、发布、删除、推送），在它前面插检查点 |

### P2 · 具体性与入口

| 码 | 修法 |
|---|---|
| `SP001` | 逐处替换（见 §4 对照表）。**软化措辞的本质是把决定权推回给 agent**，等于没写 |
| `SP002` | 给关键步骤补一条**可复制**的命令或最小示例 |
| `SP003` | 并列的判据 / 分支改成表格 |
| `FM005` | 让 `name` 与目录名对齐（目录名的 `-skill` 后缀可省） |
| `FM007` | 补触发词，**用用户真会说的原话**，不是关键词堆砌 |
| `FM008` | 删空话尾巴，换成具体适用条件 |
| `FM009` | 补一行「不适用：…」。**注意缩进**——顶格写会掉出 `description`（见 §3） |

### P3 · 结构与体积

| 码 | 修法 |
|---|---|
| `ST001` / `ST010` | 只留一个 H1，其余降级为 H2 |
| `ST002` / `ST003` | 补流程章节，写成有序步骤（Phase 表也算） |
| `ST005` | 补「时机 → 读哪个文件」的路由表，避免 agent 全量预读 |
| `ST006` | 补反例黑名单，见 §5 |
| `ST007` | 补输出契约：交付报告哪几项、什么不许声称 |
| `ST008` | 补可勾选的验收 checklist |
| `ST009` / `SZ001` | 把细节下沉到 `references/`，正文只留路由与判据 |
| `SZ002` | README 与 frontmatter 的 `name` 对齐 |

### P4 · 安全

| 码 | 修法 |
|---|---|
| `SF001` | 在黑名单里明文列禁 + 给替代做法。**不要只是删掉命令**——写出来才能被识别 |
| `SF002` | 补一行：不得把凭证 / 密钥写入产物或日志 |

## 3. 入口模板（修 `FM003` / `FM007` / `FM009` 时用）

```yaml
description: |
  <一句话说做什么>。

  适用：用户说「<原话 1>」「<原话 2>」「<原话 3>」；<场景补充>。
  不适用：<不要用的场景>；<另一个不要用的场景>。
```

**三条纪律**：

1. **全部行保持缩进**——顶格写会让那一行掉出 `description`（`FM009` 报的就是这个）
2. 触发词用**用户真会说的原话**，不是「关键词」
3. 总长 ≤ 1024 字符

## 4. 软化措辞对照表（修 `SP001`）

| 软化措辞 | 改成 |
|---|---|
| 建议先读 X | 读 X |
| 可以考虑用 Y | 用 Y |
| 根据情况调整 | 给出判据：「若 A 则 X；若 B 则 Y」 |
| 灵活把握 / 视情况而定 | 写死默认值 + 说明何时覆盖它 |
| 尽量 / 如有必要 | 删掉，或换成明确的触发条件 |
| 或许 / 大概 | 给出确定的判据，或标为「未知」 |

**判据**：改完之后，agent 还需要自己做决定吗？**需要 → 还没改完。**

## 5. 反例黑名单模板（修 `ST006` / `SF001`）

```markdown
## 反例黑名单

| # | 不要做 | 为什么 | 替代做法 |
|---|--------|--------|---------|
| 1 | 用 `git reset --hard` 回滚 | 会丢工作区未提交改动 | 用 `git revert` 建反向提交 |
| 2 | 静默跳过异常 | 破坏可追溯性 | 先告知用户再按规则处理 |
```

**每条必须给替代做法**——只说「不要做 X」而不说「那做什么」，
agent 在必须推进时还是会走回 X。

## 6. 高杠杆操作（实测有效）

| # | 操作 | 效果 |
|---|---|---|
| **HL-1** | 加 `🔴 CHECKPOINT` / `🛑 STOP` 视觉标记 | 4 行改动撬动 dim4 大幅提升。LLM 扫的是视觉锚，不是措辞 |
| **HL-2** | 失败表升级为三段式（触发条件 / 一线修复 / 仍失败兜底） | 第三列是质变：它回答「第二次失败怎么办」 |
| **HL-3** | 诊断存在**相关簇**：dim2 / dim3 / dim4 | 修 dim3 时 dim2 常跟着涨。找最大短板时**同时看整簇**，别单独攻 |
| **HL-4** | 触顶就停 | 连续 2 轮 `margin=slight` 或 `tie` → break。硬凑轮次只会引入过度设计 |
| **HL-5** | 下沉细节到 `references/` | 正文从 600 行降到 300 行，`ST009`/`SZ001` 消失，且按需读取省上下文 |

## 7. 加权短板：先改哪个维度

```
weighted_gap(dim) = weight(dim) × (10 − score(dim)) / 10
```

**这个值就是该维度还能贡献的总分数。** 选 `weighted_gap` 最大的维度动手。

**不要用「原始分最低」**：低权重维度会制造进步幻觉。实测案例——dim9（权重 6）原始分最低
被优先修，而 dim8（权重 23）加权短板最大却 4 轮未动。

**回退规则**：两个维度的 `weighted_gap` 差距 ≤ 1.0 时，按原始分升序。
**相关簇规则**：见 HL-3。
